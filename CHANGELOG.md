# Changelog

## 2026-11-18

- fix(retry): add `scripts/http_retry.py`, a shared stdlib bounded full-jitter backoff helper (default 3 attempts, 0.5 s base, 8 s cap, ~20 s budget; `DIALPAD_HTTP_RETRIES`/`DIALPAD_HTTP_RETRY_MAX_SLEEP` overrides; honors `Retry-After` seconds and HTTP-dates; injectable sleep/randomness) plus the send SAFE-RETRY classifier: `sms send` is not idempotent, so it retries only HTTP 429 and provable connect-stage failures (DNS, refused, connect timeout); read timeouts, mid-flight resets, and 5xx map to the new `send_outcome_unknown` error code ("check the thread before resending"), while other 4xx are permanent. The same rule covers every non-idempotent generated command — anything carrying `--data` or a write verb (`call.call`, `*create`, `*update`, `*delete`) — with non-SMS commands reporting "request outcome unknown; verify before repeating"; `*list`/`*get` reads retry any transient failure. `bin/_dialpad_compat.py` applies the classification inside `run_generated_json` and carries `error.retry_after_seconds` in envelopes; `scripts/send_sms.py` direct fallback implements the same rule for urllib.
- fix(log_client): `scripts/log_api_client.py` retries shared-log GETs on 429/408/5xx and `URLError`/timeout/reset, marks 429/408/5xx `retryable` after exhaustion (other 4xx permanent), and treats a 200 whose body lacks `data` or a required list (`messages`, `calls`) as a retryable `upstream_error` instead of an empty result; `POST /v1/sms/record` stays single-attempt because the outbox replays it. `bin/list_sms_thread.py` (via the new importable `read_thread_summary`), `bin/list_sms_inbox.py`, and `bin/list_calls.py` declare their required keys and turn generic exceptions into the standard error envelope.
- fix(envelope): every handled wrapper failure in `--json` mode — including uncaught exceptions — prints the `{"ok": false, "error": {code, message, retryable}}` envelope with no `data` key and exits 2; callers must branch on `error.retryable` and never index `data` before checking `ok`.
- fix(receipts): `scripts/sms_receipts.py` resolves the ledger path at append time as `DIALPAD_SMS_RECEIPT_LEDGER` → legacy `/data/.openclaw/state/dialpad/sms-receipts.jsonl` when its directory is usable → `${XDG_STATE_HOME:-~/.local/state}/dialpad/sms-receipts.jsonl` (mode-0700 parents), retrying the XDG path once on `OSError` and never raising.
- feat(send_sms_at): add `bin/send_sms_at.py`, a scheduled send that waits until a recipient-local `--at` time (IANA `--tz`, defaulting to the recipient's NANP area-code zone; blocked minutes and the 08:00-21:00 window enforced like the send gate), then re-reads the thread and skips — exit 0, `data.status: "skipped"` with `reasons` — on inbound opt-out text, any outbound in 24 h, a second outbound in 7 days (`WEEKLY_OUTBOUND_CAP`), any inbound in 24 h, or an unreadable thread (`thread_unreadable`); `--check-only` reports the decision without waiting, and the actual send is a `bin/send_sms.py` subprocess so the gate, receipts, and approval audit still apply.
- test(retry): cover the helper, the classifier table, log-client retry/exhaustion/shape cases, wrapper envelope audit, direct-send safe retries, ledger path resolution, and the scheduled-send decision paths; no network or real sleeps.

## 2026-11-17

- feat(send_gate): make the 08:00-21:00 recipient-local send window advisory instead of a hard block — it stays the recommended refuse-by-default check, but an outside-window refusal now carries the stable `outside_recommended_window` reason code (new `Decision.reason_codes`, aligned with `reasons` and surfaced in `public()`) and says to pass `allow_outside_window=true` to send anyway. `evaluate_send`/`evaluate_from_environment`/`evaluate_approved_send`, both send CLIs (`--allow-outside-window`), `send_api_server.execute_gated_send`, and the team MCP `send_sms` tool (strict boolean, forwarded to the child argv, `reason_codes` in tool errors, override logged in the audit line) accept the opt-in; the HTTP send API body still rejects the field. A used override is recorded on the decision (`overrides` in `public()`, `receipt_context()`, `details`) plus a stderr "send gate override used" notice, and a flag passed while inside the window records nothing. Opt-out union, caller/line allowlist, area-code, config, and support-line checks stay hard; the minute rule is never overridable and now also binds zones the override waived.
- feat(team_mcp): add read-only call tools `list_calls` and `get_call` to the team MCP connector (server info 1.1.0), backed by new `scripts/team_calls.py` — a stdlib, GET-only Dialpad client for `/call` (cursor list, no `limit` param), `/call/{id}`, `/transcripts/{id}`, and `/call/{id}/ai_recap` with an injectable transport and a 300 s bounded TTL cache of raw upstream responses (never an allow decision; scoping is re-evaluated per caller per request). Call scoping: a call belongs to `{internal_number, entry_point_target.phone}` normalized to 10-digit keys, visible only when one of those lines is in the caller's allowed set and none is the support line — so shared-line calls forwarded to a teammate show via the entry point while another teammate's direct-line call stays hidden; `get_call` refuses disallowed calls and nonexistent ids with one identical generic `call_not_found` before any transcript/recording/recap fetch, so call ids cannot be probed across lines. `list_calls` filters the company-wide list client-side (up to 12 pages / 300 raw calls, `scanned`/`truncated`/`lines` reported) with `line` (E.164 or office/sales/teammate/`own` alias, `line_not_allowed` refusal), `since`/`until`, and `limit`; `get_call` returns the summary plus on-request `transcript` (lines split from moments, bounded `transcript_text`), `recording` (urls with the not-pre-signed-URL note, get_call only), and `recap` sections that each degrade to `{available: false, reason, message, retryable}` on 404/403/rate-limit/other failures — only the call lookup is a hard error. Recording/voicemail URLs never appear in list output or logs; a missing `DIALPAD_API_KEY` returns `not_configured` while the server keeps working.
- test(team_mcp): cover the call tools end-to-end with a fake Dialpad client and fake transport — per-caller line scoping (sales-forwarded visibility, other-teammate and support-line exclusion), `line` filter and refusals, since/until/limit validation, pagination `scanned`/`truncated`, status derivation (answered/missed/voicemail/no_answer), no URLs in list output, identical generic refusals for disallowed vs nonexistent ids with no section fetches, happy-path transcript+recording+recap, per-section degradation, transport error mapping including the HTTP-400 `rate_limit_exceeded` form, missing-key `not_configured`, and cache isolation across callers.
